## 배경

리더는 **문서 형식을 아는 마지막 계층**이다. 위로는 `OutlineNode[]`만 흐른다.
여기서 무엇을 버리면 아래 어느 계층도 복구하지 못한다.

`markdown-reader`가 제품 경로가 아니라는 사실(`ADR-010`)이 이 파일을 덜 중요하게 만들지 않는다.
**아웃라인 로직 전체가 이 리더의 출력으로 검증된다.** `docx-reader`(step 6)는 이 리더와 같은
출력을 낸다는 것만 증명하면 된다.

## 작업

### 1. `src/lib/doc/markdown-reader.test.ts` 를 **먼저** 쓴다

시그니처를 고정한다:

```ts
export function readMarkdownOutline(markdown: string): OutlineNode[];
```

케이스 (전부 문자열 리터럴로 만든다 — 픽스처 의존 케이스는 마지막 하나뿐):

| 입력 | 기대 |
|---|---|
| `# 제목` | `{level:1, text:'제목', lines:[]}` |
| `### 1-2. 과제 (中上)` | `text`가 **원문 그대로**. 번호·괄호를 자르지 않는다 |
| 제목 아래 `- 항목` | 직전 노드의 `lines`에 `'항목'` (불릿 기호·앞 공백 제거) |
| `* 항목` · `+ 항목` · `1. 항목` · `① 항목` | 같은 규칙. **기호만 떼고 텍스트는 보존** |
| 들여쓴 불릿 (`  - 하위`) | 같은 `lines`에 평평하게. 깊이는 버린다 |
| 빈 줄 | 무시 (`lines`에 빈 문자열을 넣지 않는다) |
| 일반 문단 줄 | 그대로 `lines`에 |
| 제목 앞에 나온 본문 줄 | **버리지 않는다.** 어느 노드에도 안 붙으므로 → 아래 규칙 참조 |
| `#####` (level 5) | `level:5`. 6까지 받는다 |
| `#제목` (공백 없음) | 제목이 아니다. 본문 줄로 취급 |
| 빈 문자열 · 공백뿐 | `[]` |
| 픽스처 전체 | 과제 제목 6개 이상이 `level:3`으로 잡히고, `## 워크로드 공유`가 `level:2`로 있다 |

**제목 앞 본문 줄**: 리더가 값을 버리지 않게 `level:0`짜리 서두 노드 하나를 만들어 담는다.
(`text`는 빈 문자열.) 상위 계층은 `level:0`을 과제로도 대분류로도 보지 않으므로 안전하다.
버리는 쪽을 택하지 않는 이유는 `CLAUDE.md`의 「파서는 값을 보존한다」다.

### 2. `src/lib/doc/markdown-reader.ts` 를 구현한다

- 줄 단위로 훑는다. 정규식 하나(`/^(#{1,6})\s+(.*)$/`)가 제목을 가른다.
- 불릿 기호 제거: `-`·`*`·`+`·`1.`·`1)`·`①`~`⑳`·`•`. **제거는 줄 맨 앞 한 번만** 한다
  — 본문 안의 `-`를 지우면 `2026-08-23`이 망가진다.
- `text`·`lines`는 `trim()`만 한다. 그 밖의 정규화(전각→반각, 공백 접기)를 하지 마라.
  판단은 위 계층의 일이고, 여기서 손대면 원문 대조가 불가능해진다.
- 코드 펜스(` ``` `)는 신경 쓰지 않는다. 픽스처에 없고, 있으면 그냥 본문 줄이다.
- 예외를 던지지 않는다. 어떤 문자열을 넣어도 배열을 돌려준다.
- `mammoth`·`node-html-parser`·`exceljs`를 import하지 마라. 이 파일은 문자열만 안다.
