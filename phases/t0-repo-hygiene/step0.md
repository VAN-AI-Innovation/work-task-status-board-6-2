# Step 0: repo-cleanup

## 읽어야 할 파일

먼저 아래 파일들을 읽고 프로젝트의 아키텍처와 설계 의도를 파악하라:

- `CLAUDE.md` — CRITICAL 규칙 전부
- `docs/TICKETS.md` — `## T0 · 저장소 위생 정리 및 테스트 게이트 복구` 절
- `docs/UI_GUIDE.md` — 「디자인 원칙」과 「AI 슬롭 안티패턴 — 하지 마라」 표
- `src/app/page.tsx` · `src/app/layout.tsx` — 지금 지워야 할 보일러플레이트
- `.gitignore`

## 배경

이 저장소는 `create-next-app` 템플릿과 다른 데모 리포의 잔재가 섞여 있다. T0는 제품 코드를
쓰기 전에 그 잔재와 개인정보 유출 경로를 먼저 걷어내는 단계다. 이 step은 그중 **정적 잔재
삭제와 `.gitignore` 보강**만 맡는다.

## 작업

### 1. `.gitignore` 보강

다음 두 항목을 추가하라. 기존 줄은 건드리지 마라.

- `.turbo`
- `.claude/settings.local.json`

`.claude/settings.json`(공유 설정)은 **커밋 대상이다.** 무시 목록에 넣지 마라.

### 2. 데모 잔재 삭제

- `index.html` — 저장소 루트의 1줄짜리 파일. 삭제한다.
- `public/file.svg` · `public/globe.svg` · `public/next.svg` · `public/vercel.svg` · `public/window.svg`
  — create-next-app 기본 에셋 5개 전부 삭제한다. `public/` 디렉토리 자체는 남긴다.

`index.html`은 `.github/workflows/proof-html.yml`이 유일하게 검사하던 파일이다. 이 워크플로우는
**step 4에서 교체**하므로, 이 step 직후 잠시 CI가 깨진 상태가 된다. 정상이다. 워크플로우 파일은
이 step에서 건드리지 마라.

### 3. `src/app/page.tsx` 교체

현재 파일은 `next/image`로 `/next.svg` 등을 렌더하는 create-next-app 랜딩이다. 위에서 SVG를
지우므로 **같은 step에서 반드시 교체**해야 빌드가 깨지지 않는다.

교체 내용은 **플레이스홀더 한 화면**이다. 프로젝트 이름과 한 줄 설명 정도만 둔다.

- `next/image` import를 남기지 마라. 렌더할 이미지가 없다.
- Tailwind 유틸리티 클래스만 쓴다. 새 CSS 파일이나 `globals.css` 수정은 하지 마라.
- `docs/UI_GUIDE.md`의 「AI 슬롭 안티패턴」 표에 있는 것을 하나도 쓰지 마라
  (그라데이션 텍스트, blur 배경, 네온 글로우, 보라/인디고 브랜드 색, 장식용 orb 등).
  이유: 이 프로젝트의 톤은 "도구처럼 보여야 한다"로 확정돼 있다.

### 4. `src/app/layout.tsx` 메타데이터 교체

`metadata.title`이 `"Create Next App"`, `description`이 `"Generated by create next app"`으로
남아 있다. 브라우저 탭에 그대로 노출되는 데모 잔재다. 프로젝트에 맞는 값으로 바꾸고,
`<html lang="en">`을 `lang="ko"`로 고쳐라.

`Geist` 폰트 설정, `className`, `body` 구조는 **그대로 둔다.** 이 step의 범위가 아니다.

## Acceptance Criteria

```bash
npm run lint     # 경고·에러 없음
npm run build    # 컴파일 에러 없음
```

추가로 아래가 모두 참이어야 한다:

```bash
test ! -e index.html                          # 삭제됨
test -z "$(ls public/*.svg 2>/dev/null)"      # SVG 5개 삭제됨
grep -q '^\.turbo$' .gitignore
grep -q '^\.claude/settings\.local\.json$' .gitignore
! grep -q 'next/image' src/app/page.tsx
! grep -q 'Create Next App' src/app/layout.tsx
```

## 검증 절차

1. 위 AC 커맨드를 전부 실행한다.
2. 아키텍처 체크리스트를 확인한다:
   - `CLAUDE.md`의 CRITICAL 규칙을 위반하지 않았는가?
   - `src/app/page.tsx`가 props 없이 JSX만 뱉는가? (계산 로직이 들어가면 안 된다)
3. 결과에 따라 `phases/t0-repo-hygiene/index.json`의 step 0을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- 대시보드·차트·업로드 화면을 만들지 마라. 이유: 각각 T6·T5 범위이고, T0의 범위 Out에
  "제품 코드. 파서·도메인·화면은 T2 이후"로 명시돼 있다.
- `.github/workflows/` 아래 파일을 건드리지 마라. 이유: step 4의 범위다.
- `package.json`을 수정하지 마라. 이유: step 1·2의 범위다.
- `src/lib/`에 파일을 만들지 마라. 이유: 이 step은 정적 잔재 삭제만 한다.
- `git commit`을 직접 실행하지 마라. 이유: 커밋은 하네스가 확정된 제목으로 처리한다.
- 기존 테스트를 깨뜨리지 마라.
