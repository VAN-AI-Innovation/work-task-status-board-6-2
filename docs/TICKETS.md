- **예상**: XS · **선행**: T0 · **브랜치**: `chore/#N`

**목적**
T7(독스→배정표)과 T5(업로드 한도)가 딛고 선 **미검증 전제 2건을 30분 안에 실측**한다. 둘 다 틀리면 설계가 바뀌는데, 구현을 반쯤 한 뒤 발견하면 되돌리기가 비싸다. PLAN.md가 이걸 「확인 필요」 메모로만 두고 있어 건너뛰기 쉬웠다 — 그래서 티켓으로 승격했다.

**범위 In**

1. **mammoth 스모크** (`H8`) — 실제 Google Docs(`[VAN] AI혁신부 26-2 워크로드`)를 `.docx`로 내보내 `mammoth.convertToHtml`이 `## N. 대분류` → `h2`, `### N-M. 과제명` → `h3`으로 인식하는지 확인한다. Google Docs 내보내기의 스타일 이름은 표준이 아닐 수 있다.
2. **시트 크기 실측** (`A7`) — 실제 시트(`[VAN] 26-2 컨텐츠마케팅부 업무_`)를 `.xlsx`로 내보내 파일 크기를 잰다. 앱 업로드 한도는 4MB로 정해져 있다 (Vercel 서버리스 본문 한도 4.5MB보다 확실히 아래).
3. 결과를 `PLAN.md`의 `H8`·`A7` 항목에 반영한다. 실패 시 대안까지 확정한다.

**인터페이스 경계** (`A1`·`A2` / `ADR-005`·`ADR-006`)

`TaskRepository`는 **저장·조회만** 한다. 집계·판정은 전부 `lib/domain/`의 JS 순수 함수이며 **SQL 집계를 쓰지 않는다** — 두 구현의 결과 일치가 성능보다 중요하다.

```
listTasks(filter) → Task[]        upsertTasks(tasks) → { created, updated, unchanged }
getTask(id) → Task | null         listStages(taskIds) → Stage[]
listGoalMetrics(filter) → GoalMetric[]              upsertGoalMetrics(metrics)
recordEvents(events)              getLastSyncedAt() → timestamp
```

폴백은 **읽기 전용**이다. 폴백 중 쓰기는 `503`을 반환하고, 배너는 "읽기 전용 — 저장소 연결 실패"로 의도된 데모 모드(`STORAGE_DRIVER=memory`)와 문구를 구분한다.

**리스크·미결**

4. 생성 xlsx의 `상태`·`난이도`·`우선순위` 컬럼에 드롭다운이 붙는다
5. **수식 주입 방어**: `=`·`+`·`-`·`@`·탭·개행으로 시작하는 값이 텍스트로 강제되거나 `'` 프리픽스가 붙는다. `=cmd|'/c calc'!A1`을 담은 픽스처로 검증 (`S1`, `ADR-012`, **필수**)
6. **왕복 테스트 통과**: md 픽스처 → rows → xlsx → 시트 파서로 재파싱 → rows 동일

**리스크·미결**

- `9/1`의 연도 추론 → `baseYear` 파라미터 주입, 실패 시 `deadline_raw`만 보존하고 `deadline_date`는 null. 하드코딩 금지.
- mammoth의 Google Docs 스타일 인식(`H8`)은 **T1에서 판정이 끝났다 — PASS.** 기본 옵션에서 `h2` 12건·`h3` 50건이 인식되며 **styleMap 커스터마이즈가 필요 없다.** `docx-reader.ts`는 `mammoth.convertToHtml({ path })`를 옵션 없이 호출한다. **예상 `L`을 재산정 없이 유지한다.** 문단 텍스트 패턴 매칭 대안은 쓰지 않는다. 근거: `scripts/smoke/RESULT.md`「H8」
- 다만 `h3` 50건 중 **아웃라인 과제는 `N-M.` 접두사를 가진 20건이고 나머지 30건은 절 제목**이다. `outline-builder`는 태그 깊이만이 아니라 **번호 접두사도 함께** 보고 과제를 골라야 한다.
- 「워크로드 공유」 섹션의 P0/P1과 ①②③④는 별도 블록이므로 `workload-parser.ts`로 분리 파싱 후 과제 번호로 조인해 `priority`를 채운다. 조인 실패는 무시.

## T8 · 인증 + RLS + 권한별 UI 게이팅

- **예상**: L · **선행**: T6 · **브랜치**: `feat/#N`

**목적**
과제 원문 요구 6번(권한별 열람·수정 범위 구분)을 충족한다. T6까지는 `?as=` 쿼리로 역할을 흉내 냈을 뿐 **실제 방어가 없다.** 여기서 서버가 실제로 거부하게 만든다.

**범위 In**

- Supabase Auth 로그인 + `profiles` 테이블 (`role`: `admin` / `lead` / `member`)
- `members.auth_user_id` 연결 — 시트의 담당자 이름과 로그인 계정을 잇는다
- RLS 정책 (5개 남짓) + `security definer` 함수 `my_role()`·`my_team()`
- 역할별 UI 게이팅 — `admin` 전사 / `lead` 자기 팀 / `member` 본인 건
- `PATCH /api/tasks/[id]` 서버 측 권한 검증 (`UC-16`)
- `?as=` 역할 전환의 프로덕션 차단 (`S4`)

**범위 Out**
초대·가입 플로우, 비밀번호 재설정, 소셜 로그인. 계정은 수동 생성으로 충분하다.

**산출물**
`supabase/migrations/` RLS 마이그레이션 + `src/lib/store/` 인증 클라이언트 + 로그인 화면

**완료 기준**

1. 세 역할로 로그인해 각각 다른 범위가 보인다 — `admin` 전사 / `lead` 자기 팀 / `member` 본인 건
2. **`member`가 타인의 태스크에 `PATCH`를 보내면 서버가 `FORBIDDEN`으로 거부한다.** UI 숨김은 방어가 아니므로 `curl`로 직접 검증한다 (`UC-16`)
3. **RLS 정책이 무한 재귀하지 않는다** — 정책 안에서 `profiles`를 직접 select하지 않고 `security definer` 함수로 감쌌다
4. **`my_role()`·`my_team()`에 `set search_path = ''`가 고정**되고 스키마가 명시돼 있다 (`S5` — 없으면 권한 상승 경로가 된다)
5. **조회가 사용자 JWT로 나가 RLS가 실제로 걸린다.** `service_role` 키는 서버의 업로드 커밋·시드 경로에만 쓰인다 (`A3`)
6. **프로덕션 빌드 + Supabase 연결 상태에서 `?as=admin`이 무시된다** (`S4`, `ADR-013` — 남아 있으면 완전한 인증 우회다)
7. 로그아웃 상태에서 보호된 라우트에 접근하면 로그인으로 리다이렉트된다

**리스크·미결**

- **RLS를 켜는 순간 기존 화면이 전부 빈 데이터로 보일 수 있다.** 정책을 먼저 쓰고 켠다.
- 시트의 담당자는 **자유 입력 문자열**이라 `auth_user_id`와 1:1로 안 붙는 이름이 남는다. 매칭 실패는 `unknown_owner`로 두고 `member` 범위 판정에서 제외한다.
- 이 티켓은 잘라야 할 때 T10 다음으로 밀리는 순서다. 다만 요구 6번이 여기 있으므로 **미루면 과제 요구가 하나 빈다.**

## T9 · 배포 + README + 주간 보고 전용 화면

- **예상**: M · **선행**: T6, T7 · **브랜치**: `feat/#N`

**목적**
심사자가 **클론하지 않고도** 볼 수 있는 URL을 확보하고, 클론했을 때 `.env` 없이 바로 돌아가는지를 문서로 보증한다. 더불어 요구 5번(대표·실장용 주간 보고서)의 전용 화면을 완성한다.

**범위 In**

- Vercel 배포 + 환경변수 설정 + `.env.example`
- `README.md` — 스크린샷, 로컬 실행법(`STORAGE_DRIVER=memory`), 배포 URL, 과제 요구 대조표
- `/report` 주간 보고 전용 화면 — T6의 브리핑 카드를 확장 (기간 선택, 팀별 섹션, 마크다운 복사·다운로드)
- T6에서 밀린 항목이 있으면 여기서 흡수

**범위 Out**
자동 스케줄링(주간 배치 발송)은 T10 영역이다. 여기서는 **사람이 열어서 복사**하는 화면까지.

**산출물**
배포 URL + `README.md` + `src/app/report/page.tsx`

**완료 기준**

1. **배포 URL이 열리고 샘플 데이터로 대시보드가 렌더된다.** 로컬이 죽어도 URL, URL이 죽어도 로컬 — 이중화가 목적이다
2. **`.env` 없이 클론 → `npm install && npm run dev` → 빈 상태 → `[샘플 데이터 불러오기]` → 대시보드**가 성립한다 (`PRD.md` 성공 기준 1번)
3. `README.md`에 로컬 실행법·배포 URL·과제 요구 7개 대조표가 있고, 실행법대로 따라 하면 실제로 뜬다
4. `/report`에서 주간 보고 마크다운이 생성되고 복사·다운로드된다 (`UC-08`)
5. `.env.example`에 필요한 키가 모두 있고 **실제 키 값이 들어 있지 않다**
6. 배포 환경에서 **업로드 4MB 한도가 실측으로 재확인된다** (`A7` — Vercel 서버리스 본문 한도는 앱 한도보다 먼저 걸릴 수 있다)

**리스크·미결**

- Supabase 무료 티어는 7일 미접속 시 프로젝트를 일시중지한다. **발표 직전 반드시 깨워 둔다.**
- 배포 환경변수에 `service_role` 키를 넣을 때 `NEXT_PUBLIC_` 접두사가 붙지 않았는지 확인한다 (T0의 빌드 가드가 잡아야 하지만 배포 설정은 코드 밖이다).
- 스크린샷에 실명·연락처가 찍히지 않도록 익명화 시드로 촬영한다.
- **`TaskRepository`에 이벤트 조회 메서드가 없다.** `recordEvents`(쓰기)만 있고 읽는 길이 없어
  `GET /api/report/weekly`가 `buildWeeklyReport`에 `events: []`를 넘긴다 — 보고서의
  「이번 주 변경 건수」가 0으로 나간다. 없는 숫자를 지어내지 않기로 한 결과다(T5 step 8).
  실제 건수를 채우려면 인터페이스에 `listEvents(filter)`를 더해야 하고, 그 작업의 자리는
  사이드 패널의 「최근 변경 이력」을 그리는 T6이거나 `/report` 전용 화면을 만드는 **이 티켓**이다.

## T10 · 알림 발송 (디스코드 웹훅) — 여유 있을 때만

**범위 In**

- 디스코드 웹훅 발송 — T6의 `collectAlerts` 결과를 포맷해 전송
- 발송 트리거는 **수동 버튼 + 수동 실행 스크립트**까지. 자동 스케줄은 범위 밖
- 중복 발송 방지 — 같은 알림을 반복 전송하지 않도록 발송 이력 기록

**범위 Out**
메일 발송, 자동 크론 스케줄링, 개인별 DM. 채널 하나에 요약 한 건으로 충분하다.

**산출물**
`src/lib/domain/alert-dispatch.ts` + 발송 API 라우트 + `.env.example`에 웹훅 URL 키 추가

**완료 기준**

1. 알림 4종(마감 임박 / 장기 미갱신 / 담당자 미지정 / 기한 미설정)이 디스코드 메시지 하나로 전송된다
2. **웹훅 URL이 없으면 조용히 skip하고 앱은 정상 동작한다** — 키 없이 전 기능이 돌아야 한다는 원칙(`PRD.md` MVP 제외 사항)을 깨지 않는다
3. 같은 알림이 연속 실행에서 중복 전송되지 않는다
4. **발송 메시지에 실명·연락처가 담기지 않는다** (`S6` — 디스코드는 외부 서비스다)

**리스크·미결**

- 웹훅 URL은 시크릿이다. 커밋 금지, `.env.example`에는 빈 값만.
- 디스코드 메시지 2000자 제한. 알림이 많으면 잘리므로 상위 N건 + "외 M건"으로 요약한다.
