# PRD: 전사 업무 현황판 고도화 (work-task-status-board)

> 근거 문서는 `docs/PLAN.md`다. **결정이 바뀌면 PLAN.md를 먼저 고치고** 이 문서를 맞춘다.
> 과제: VAN AI Innovation 학회 **6-2. 전사 업무 현황판 고도화 (中上)**. 1인 개발(갠플), 웹.

## 목표

Google Sheets 한 파일에 팀별로 **16 / 70 / 20 컬럼**씩 제각각 흩어진 업무 현황을,
**시트를 올리는 것만으로** 통합 조회·판정할 수 있게 한다.

## 담당자 지시 = 최우선 기준

> "엑셀 시트 **입력 시 업무 파악을 빠르게 조회하거나 파악**할 수 있는 기능 추가해주시면 될 것 같습니다.
> 그리고 **독스 파일 입력 시 저희 업무 배정표처럼 엑셀시트로 뽑을 수 있는** 기능 이렇게 추가하면 됩니다"

평가 대상 산출물은 **두 개**다. 과제 원문의 나머지는 이 둘을 떠받치는 형태로만 구현한다.

1. **엑셀 넣으면 → 빠르게 조회·파악** (파서 + 대시보드 + 조회 UX)
2. **독스 넣으면 → 업무 배정표 엑셀이 나옴** (아웃라인 파서 + xlsx 생성)

두 기능은 **한 바퀴로 닫힌다** — 뽑은 배정표를 채워 다시 업로드하면 현황판에 반영된다.

## 제품의 위치 — 가장 중요한 전제

**이 웹은 Google Sheets를 대체하지 않는다.** 담당자가 "엑셀시트 **입력 시**"라고 규정한 순간,
데이터 입력은 시트에 남고 이 웹은 그것을 **읽고 해석하는 층**이 된다.

```
 [입력 계층]  Google Sheets   ← 팀원이 평소처럼 입력. 바뀌지 않는다.
      ↓            (내보내기)
 [해석 계층]  이 웹           ← 정규화 · 판정 · 시각화 · 조회
      ↓
 [소비 계층]  대시보드 · 주간 브리핑 · 배정표 xlsx
```

- **강점**: 기존 업무 습관을 안 바꾼다. 채택률의 전부가 여기 달렸다.
- **약점**: 업로드하지 않으면 데이터가 낡는다. **설계로 감추지 않고 화면에 드러낸다** —
  모든 페이지에 "마지막 반영: N일 전"을 상시 표시하고 5일 초과 시 경고색.

## 사용자

| 역할 | 누구 | 빈도 | 목적 | 성공 기준 |
|---|---|---|---|---|
| **운영자** | AI혁신부 담당(본인) | 주 1~2회 | 시트·독스를 올려 데이터 갱신 | 드롭 → 확정까지 3분 |
| **대표·실장** `admin` | 조직 임원 | 주 1회 (회의 직전) | 전사 현황 파악, 의사결정 사항 추출 | 한 화면에서 5분 안에 브리핑 완성 |
| **팀장** `lead` | 편집 / 촬영·기획 / 마케팅·관리 | 주 2~3회 | 우리 팀 병목·지연자 특정 | 지연 건과 담당자를 즉시 지목 |
| **부원** `member` | 학회원 | 주 1~2회 | 내 업무·마감 확인 | 진입 후 3초 안에 "내 마감" 확인 |

**운영자는 과제 원문에 없는 페르소나지만 데이터가 들어오는 유일한 경로**다.
이 사람이 귀찮으면 시스템 전체가 죽는다.

## 핵심 기능

1. **시트 업로드 → 미리보기 → 확정** (`/upload`) — 신규 N · 변경 M · 유지 K · 경고 W를 보여주고
   확정 전에는 저장소에 아무것도 쓰지 않는다. **부분 업로드**(자기 팀 탭만) 지원.
2. **독스 → 배정표 xlsx** (`/extract`) — `.docx` 아웃라인을 파싱해 상태·난이도·우선순위에
   **드롭다운이 박힌** xlsx를 생성. 사람이 이어서 입력할 수 있는 파일이어야 한다.
3. **통합 대시보드** (`/`) — 시트 `00_통합 대시보드` 탭과 1:1 대응. KPI 10종, 팀별 요약·차트,
   목표 대비 성과, 확인 필요 업무, 마감 일정, 승인 대기함, 알림 패널, 주간 브리핑 카드.
4. **부서별 탭** (`/teams/[teamSlug]`) — 공통 8~10컬럼 표 + 사이드 패널에 팀 전용 필드 전량.
5. **빠른 조회 UX** — 필터·정렬·검색, **필터 상태를 URL 쿼리에 유지**(링크 공유), `?owner=` 프리셋,
   `?task=` 딥링크.
6. **상태 5색 구분과 알림 4종** — 예정·진행·검토·완료·지연 / 마감 임박·장기 미갱신·담당자 미지정·기한 미설정.
7. **권한별 열람·수정** — Supabase Auth + RLS (`admin` / `lead` / `member`).

|---|---|---|

| 2 | 예정·진행·검토·완료·지연 상태 시각적 구분 | `toDisplayStatus` 5색 + 배지 (T6) |
| 3 | 마감 임박·장기 미갱신·담당자 미지정 자동 알림 | 알림 패널 4종 (T6). **발송은 T10** |
| 4 | 부서별 목표와 실제 성과 비교 | `goal_metrics` + 성과 섹션 (T3·T6) |
| 5 | 회의 전 자동 요약 및 대표·실장용 주간 보고서 | `weekly-report` + 브리핑 카드 (T4·T6) |
| 6 | 권한별 열람·수정 범위 구분 | Supabase Auth + RLS (T8) |
| 7 | 향후 출결·평가·경고·활동인증서 연계 | `members`를 신원 단일 소스로 (T4) |

우선순위가 충돌하면 **담당자 지시 2건이 이긴다.** 잘라야 하면 T10 → T9 → T8 순으로 밀고
T5·T6·T7은 사수한다.

## MVP 제외 사항

- **웹에서의 업무 입력·생성 UI** — 입력은 Google Sheets에 남는다 (H1 확정). 범위가 절반으로 줄었다.
- **실시간 동기화** — 웹훅 수신, 주기적 sync 배치, 웹소켓 브로드캐스팅. 데이터 소스가 외부 툴(Jira·Notion)이
  아니라 **사람이 올리는 시트 파일**이라 성립하지 않는다. 갱신은 `router.refresh()` 버튼으로 한다.
- **알림 발송** — 화면 알림 패널까지만. 디스코드 웹훅은 T10(여유 있을 때만).
- **LLM 보강** — `ENABLE_LLM=false`가 기본. 키 없이 전 기능이 동작해야 한다.
- **모바일 전용 레이아웃** — PC 우선(1280px 기준, 1024px까지 유지). 그 아래는 깨지지 않고 읽히는 수준.
- **`.docx`·`.xlsx` 이외 입력** — `.md` 리더는 **테스트 픽스처 전용**이며 제품 경로가 아니다.
- **완료 태스크 아카이빙·파티셔닝** — 수백~수천 행 규모에서 불필요.

## 디자인

- **라이트 + 무채색.** 시맨틱 색은 **2색뿐** — 빨강(지연), 앰버(주의·마감 임박). (T6 착수 시 다크로 갔다가 T6 완료 후 라이트로 복귀 — `ADR-018`)
- 도구처럼 보여야 한다. 매일 쓰는 대시보드지 마케팅 페이지가 아니다.
- 상세는 `docs/UI_GUIDE.md`. 안티패턴(글로우·gradient-text·보라/인디고·backdrop-filter blur) 위반 0건이 완료 기준이다.

## 성공 기준 (초안 마감 2026-08-31)

1. 클론 → `npm install && npm run dev` → **`.env` 없이** 빈 상태에서 `[샘플 데이터 불러오기]`로 대시보드가 뜬다.
2. 실제 시트를 올려 드롭→확정이 **3분 이내**, 미리보기 숫자가 시트 실제 행 수와 일치한다.
3. 실제 워크로드 `.docx`를 올려 드롭다운이 붙은 배정표 xlsx가 떨어지고, 그것을 채워 재업로드하면 현황판에 반영된다.
4. `npm run lint && npm run build && npm run test`가 통과한다.
