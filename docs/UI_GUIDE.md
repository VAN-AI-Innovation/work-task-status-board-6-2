# UI 디자인 가이드

> 톤은 `docs/PLAN.md`에서 확정된 **라이트 + 무채색, 시맨틱 2색**이다.
> 아래 색상 값은 그 제약 안에서 고른 구체값이며, 바꾸려면 이 문서를 먼저 고친다.
>
> **왜 라이트인가 (2026-08-22, T6 완료 후 · `ADR-018`)**: 이 축은 **두 번 뒤집혔다.**
> 최초 확정값이 라이트, T6 착수 시점에 다크(`ADR-015`), T6 화면을 실제로 보고 다시
> 라이트다. 세 번 다 같은 사람이 골랐다 — **톤은 취향이고 취향은 사용자의 것이다.**
> 뒤집힌 것은 매번 배경의 명도 하나뿐이고 **무채색 원칙·시맨틱 2색·AI 슬롭 안티패턴
> 규율은 한 번도 풀리지 않았다.** 참고로 제시된 이미지는 보라 액센트의 파이낸스
> 대시보드였으나, 참고한 것은 **구조**(좌측 사이드바 · 상단 바 · KPI 타일 행 · 차트 카드)
> 이지 색이 아니다.
>
> **톤은 하나뿐이다.** 다크 토글을 만들지 않는다 — 톤이 둘이면 배지 명도 방향·차트
> 계열색·스크린샷 기준이 전부 두 벌이 되고, 「이 화면이 맞느냐」를 판정할 기준이 흔들린다.

## 디자인 원칙

1. **도구처럼 보여야 한다.** 마케팅 페이지가 아니라 매일 쓰는 대시보드다. 장식은 전부 뺀다.
2. **눈에 띄는 것은 문제뿐이다.** **데이터**에서 색이 있는 것은 **지연(빨강)과 주의(앰버)**
   둘뿐이고 나머지는 전부 무채색이다. 정상 업무까지 알록달록하면 지연이 묻힌다.
   브랜드 남색은 **구조와 조작**에만 있다 (`ADR-020`) — 색이 셋으로 늘어난 게 아니라 축이
   다르다: 남색은 「여기가 어디이고 무엇을 누를 수 있나」, 빨강은 「무엇이 문제인가」다.
3. **밀도 우선.** 한 화면에 KPI 10종과 팀별 요약이 스크롤 없이 들어가야 한다(UC-07).
   여백보다 정보를 택한다.

## AI 슬롭 안티패턴 — 하지 마라

| 금지 사항 | 이유 |
|-----------|------|
| backdrop-filter: blur() | glass morphism은 AI 템플릿의 가장 흔한 징후 |
| gradient-text (배경 그라데이션 텍스트) | AI가 만든 SaaS 랜딩의 1번 특징 |
| "Powered by AI" 배지 | 기능이 아니라 장식. 사용자에게 가치 없음 |
| box-shadow 글로우 애니메이션 | 네온 글로우 = AI 슬롭 |
| 보라/인디고 브랜드 색상 | "AI = 보라색" 클리셰 |
| 모든 카드에 동일한 rounded-2xl | 균일한 둥근 모서리는 템플릿 느낌 |
| 배경 gradient orb (blur-3xl 원형) | 모든 AI 랜딩 페이지에 있는 장식 |

**위반 0건이 T6의 완료 기준이다.** 톤이 두 번 뒤집히는 동안 이 표는 한 줄도 풀리지 않았다.

라이트에서 특히 유혹이 커지는 둘을 못박는다.

- **그림자로 띄우기** — 흰 카드를 흰 배경에서 떼어 놓으려고 `box-shadow`를 겹겹이 쌓고
  싶어진다. 금지다. 카드는 **1px 테두리(`border-line`)와 배경 명도차**로만 구분한다.
  그림자를 쓰면 카드마다 높이가 생기고, 그 높이는 아무 뜻도 없다.
- **보라·인디고 액센트** — 참고 이미지가 보라 액센트였다. **채택하지 않았다.**
  AI 템플릿이 기본값처럼 쓰는 색이고, **데이터에** 액센트가 들어오면 지연이 묻힌다.
  브랜드 남색(`#1e3a5f`)은 이 항목과 다르다 — 사용자가 **실제로 가진 대표색**이고
  **구조와 조작에만** 쓴다 (`ADR-020`). 판별식은 하나다: **`chart-series.ts`·`status-badge.ts`에
  브랜드 토큰이 보이면 규칙을 어긴 것이다.** 그 둘이 데이터의 색을 정한다.

## 색상

색은 **토큰 한 곳에서만** 온다 (`src/app/globals.css`의 `@theme`). Tailwind v4가
`--color-*` 토큰에서 유틸리티를 만들므로, 화면 코드는 **hex가 아니라 아래 클래스 이름**을 부른다.

**`src/app/`·`src/components/`에서 `neutral-`·`red-`·`amber-`·`white` 같은 Tailwind
팔레트 클래스를 쓰지 않는다.** 톤이 이미 **두 번** 뒤집힌 프로젝트다. 토큰으로만 색을 부른
덕에 두 번째 전환에서 손댄 파일이 `globals.css`와 `chart-series.ts` 둘뿐이었다 (`ADR-018`).

### 배경·테두리

| 토큰 | 값 | 유틸리티 | 용도 |
|---|---|---|---|
| `--color-canvas` | `#f6f7f9` | `bg-canvas` | 페이지 배경 |
| `--color-panel` | `#ffffff` | `bg-panel` | 카드·패널·사이드바·상단 바 |
| `--color-raise` | `#f0f2f5` | `bg-raise` | 표 헤더·구분 영역·행 hover |
| `--color-line` | `#e2e5ea` | `border-line` | 테두리 |
| `--color-line-strong` | `#b9c0ca` | `border-line-strong` | 아웃라인 배지·강조 테두리 |

**카드가 페이지보다 밝다** — 패널이 흰색이고 캔버스가 옅은 회색이다. 다크에서는 반대였다.

### 텍스트

| 토큰 | 값 | 유틸리티 | 용도 |
|---|---|---|---|
| `--color-ink` | `#14171b` | `text-ink` | 주 텍스트·수치 |
| `--color-ink-body` | `#3c434d` | `text-ink-body` | 본문 |
| `--color-ink-muted` | `#697280` | `text-ink-muted` | 보조·라벨 |
| `--color-ink-faint` | `#98a1ae` | `text-ink-faint` | 비활성·물러난 것 |

### 브랜드 — 구조와 조작에만 (`ADR-020`)

| 토큰 | 값 | 유틸리티 | 용도 |
|---|---|---|---|
| `--color-brand` | `#1e3a5f` | `text-brand` · `bg-brand` · `border-brand` | 페이지·섹션 제목 / 로고 · 현재 화면 · 활성 칩 · 「적용」·기본 버튼 · 링크 hover · 입력 포커스 |
| `--color-brand-strong` | `#16304f` | `hover:bg-brand-strong` | 기본 버튼 hover |
| `--color-brand-soft` | `#eef2f7` | `bg-brand-soft` | 표 헤더 바탕 · 표 행 hover · 사이드바 현재 화면 · 접힌 줄 hover |

**데이터에는 쓰지 않는다.** 차트 계열색·상태 배지·KPI 수치·표의 값·알림 건수는 전부
무채색과 시맨틱 2색 그대로다. 쓸 자리인지 헷갈리면 묻는다 — **「이건 데이터인가,
구조·조작인가」.**

### 시맨틱 — 2색뿐

| 토큰 | 값 | 유틸리티 | 용도 |
|---|---|---|---|
| `--color-late` | `#c2181b` | `text-late` | **지연** 텍스트 |
| `--color-late-bg` | `#fdeced` | `bg-late-bg` | 지연 배경 |
| `--color-late-line` | `#dc2626` | `border-late-line` · `border-l-late-line` | 지연 테두리 (행 좌측 3px) |
| `--color-warn` | `#8a5a06` | `text-warn` | **주의** (마감 임박 D-3 이내 · 데이터 5일 이상 낡음 · 목표 미달) |
| `--color-warn-bg` | `#fdf3e0` | `bg-warn-bg` | 주의 배경 |
| `--color-warn-line` | `#d18700` | `border-warn-line` | 주의 테두리 |

**텍스트값과 테두리값이 다르다.** 흰 바탕에서 `#dc2626`은 큰 면적(테두리·막대)에는 맞지만
작은 글자로는 대비가 아슬아슬해서, 텍스트는 한 단계 어두운 `#c2181b`를 쓴다 (`ADR-018`).

**완료를 초록으로 칠하지 않는다.** 초록이 들어오는 순간 화면의 절반이 색을 갖게 되고
지연 빨강이 눈에 안 띈다. 완료는 무채색으로 **물러난다.**

## 상태 5색 구분 (과제 요구 2번)

"5색"이지만 실제 색은 2개다. 나머지 넷은 **명도와 형태**로 구분한다.

**「진행」은 가장 진한 무채색이다.** 흰 배경 위에서 가장 눈에 띄는 무채색은 가장 진한 것이고,
그것이 `bg-ink text-canvas`(검은 채움 + 흰 글자)다. 다크에서는 같은 클래스가 정반대 그림
(흰 채움 + 검은 글자)이었다 — **배지 표는 색이 아니라 의미로 적혀 있어서 토큰만 뒤집히면
명도 방향이 저절로 따라온다.** 그래서 톤 전환에서 아래 표는 한 줄도 고치지 않았다.

| 표시 상태 | 배지 스타일 | 근거 |
|---|---|---|
| **예정** | `bg-raise text-ink-muted` | 아직 안 움직임 — 배경에 가장 가깝다 |
| **진행** | `bg-ink text-canvas` | 지금 움직이는 것 — 무채색 중 가장 진하다 |
| **검토** | `border border-line-strong text-ink` | 아웃라인. 채움이 아니라 형태로 구분 |
| **완료** | `bg-panel text-ink-faint` | 끝난 것 — 물러난다 |
| **지연** | `bg-late-bg text-late` + 행 좌측 3px `border-l-late-line` | **유일하게 색을 갖는다** |

- `hold`·`cancelled`(`muted`)는 5색에 속하지 않는다. `text-ink-faint` + 배지 없이 라벨만.
- **지연은 다른 상태를 덮어쓴다.** 진행 중이면서 마감이 지났으면 "진행"이 아니라 "지연"이다.
- 배지는 색만으로 구분되지 않는다 — **항상 한글 라벨을 함께** 쓴다(색각 이상 대응).

## 컴포넌트

### 카드
```
카드:       rounded-md bg-panel border border-line p-4
KPI 타일:   rounded bg-panel border border-line px-3 py-2.5
사이드 패널: rounded-none bg-panel border-l border-line
오버레이:    bg-ink/30   ← 패널 뒤를 덮는 베일. **어두운 쪽**이다
```
**모서리 반경을 통일하지 않는다** — 위 세 값이 서로 다른 것이 의도다.
패딩은 `p-5`에서 한 단계 줄었다: 카드가 여섯 장 서는 화면이라 카드마다 8px이 첫 화면을
40px씩 밀어낸다 (`ADR-019`). 「여백보다 정보를 택한다」가 여기서 값을 치른다.
베일이 어두운 것도 라이트 전환에서 뒤집힌 값이다 — 옅은 회색을 덮으면 뒤 화면이 뿌예지기만
하고 패널이 앞에 있다는 것이 읽히지 않는다.

### 버튼
```
Primary:   rounded bg-ink text-canvas px-4 py-2 hover:bg-ink-body
Secondary: rounded border border-line bg-panel px-4 py-2 text-ink hover:bg-raise
Text:      text-ink-muted hover:text-ink underline-offset-4 hover:underline
Danger:    rounded border border-late-line text-late hover:bg-late-bg
비활성:     opacity-50 cursor-not-allowed   ← 읽기 전용 모드의 편집 버튼
```

### 알림 묶음 제목

```
제목 줄: bg-raise -mx-2 rounded px-2 py-1 · text-xs font-semibold text-ink
항목 줄: 아래 「목록 줄」 규격 (text-sm)
```

**묶음 제목에는 바탕을 깐다.** 밑줄 한 줄로는 부족했다 — 제목이 `text-xs`이고 항목이
`text-sm`이라 오히려 항목이 커 보였고, 「마감 임박」이 업무 이름인지 묶음 이름인지 한눈에
갈리지 않았다. 바탕색은 회색(`bg-raise`)이라 항목의 hover 배경(옅은 남색)과 섞이지 않는다.

**묶음은 한 번에 하나만 펼친다.** 기본은 제목 줄만 보이고, 누른 묶음이 열리면서 앞서 열려
있던 묶음이 닫힌다 — `<details name="alert-group">`의 배타 동작이라 **JS가 없다.** 항목을
전부 펼쳐 두면 이 카드가 옆 카드보다 길어져 요약이 첫 화면 밖으로 밀린다. **0건 묶음은
`<details>`로 만들지 않는다** — 눌러서 빈 상자가 열리면 목록이 빈 것인지 화면이 고장 난
것인지 알 수 없다. 건수와 「해당 없음」은 접힌 채로도 보인다.

### 목록 줄 (누르면 열리는 줄)

알림 패널·승인 대기함의 항목처럼 **누르면 사이드 패널이 열리는 줄**의 규격이다.

```
줄 전체가 링크:  -mx-2 flex items-center justify-between gap-2 rounded px-2 py-1
hover:          bg-brand-soft + 제목이 text-brand
오른쪽 끝:       › 화살표 (16px). text-ink-faint → hover 시 text-brand
```

- **이름만 링크로 두지 않는다.** 줄 전체가 누르는 자리다 — 이름 옆 빈 곳을 눌렀는데 아무
  일도 안 일어나면 사용자는 그 줄이 고장 났다고 읽는다.
- **밑줄로만 알리지 않는다.** 밑줄은 마우스를 올려야 나오므로, 올리기 전에는 눌리는 줄인지
  알 수 없다. **화살표는 정지 상태에도 보인다** — 그것이 이 줄의 어포던스다.
- 음수 마진(`-mx-2`)은 hover 배경이 카드 안쪽 여백까지 닿게 한다. 배경이 글자에만 붙으면
  줄이 아니라 조각이 강조된 것처럼 보인다.
- **줄이 스크롤 상자 안에 있으면 상자에도 `-mx-2 px-2`를 같이 준다.** 스크롤 상자는 삐져나온
  것을 자르는데, 세로 스크롤에서는 **왼쪽만** 잘려 한쪽은 각지고 한쪽은 둥근 모양이 된다.
  상자를 같은 만큼 넓히고 안쪽 패딩으로 되돌리면 글자 위치는 그대로면서 잘릴 자리가 없어진다.

### 입력 필드 · 필터 칩

**필터 바는 접어 둔다.** 칩 열여섯이 표 위에 펼쳐져 있으면 화면이 실제보다 복잡해 보이고
읽어야 할 업무 표가 아래로 밀린다. **여는 자리는 오른쪽 끝의 [필터 ⌄] 버튼**이다 — 글자만
두면 표 위 설명문과 구분되지 않아 눌리는 자리인 줄 모른다. 걸린 개수는 버튼 안의 배지로 한 번
더 말한다. 접히는 것은 **입력 수단**이고 걸린 개수는 접어도 남는다 — 필터가 걸린 줄 모르고
「데이터가 없다」고 오해하는 것이 이 화면의 가장 흔한 사고다(`X3`). 문장 한 줄(「필터 n개
적용 중」)을 따로 두지 않는 것은 **배지가 같은 사실을 더 짧게, 더 눈에 띄게** 말하기 때문이다. **필터가 하나라도 걸려 있으면 펼친 채로 시작한다.** 링크로 받은 필터가 접혀
있으면 무엇이 걸렸는지 눌러 봐야 알고, 되돌릴 [필터 초기화]도 그 안에 있다.

```
입력:    rounded border border-line bg-panel px-3 py-2 text-ink placeholder:text-ink-faint focus:border-ink focus:outline-none
칩(off): rounded-full border border-line px-3 py-1 text-ink-muted hover:text-ink
칩(on):  rounded-full bg-ink text-canvas px-3 py-1
```

### 표
```
헤더: bg-brand-soft text-brand text-xs font-medium 좌측 정렬, sticky top-0
행:   border-b border-line, hover:bg-brand-soft, 높이 40px
지연 행: border-l-[3px] border-l-late-line
숫자·날짜 컬럼: tabular-nums 우측 정렬
셀 좌우 여백: px-4, 첫 칸 pl-6 · 끝 칸 pr-6   ← 표가 카드 테두리에 붙으면 답답하다
```

**「우측 정렬」의 예외 하나** — 배정표 미리보기(`/extract`)의 `마감`은 **좌측**이다. 그 표는
대부분의 행이 마감 없는 `—`라, 오른쪽에 붙이면 빈 칸 표시만 헤더에서 멀어져 어느 컬럼 것인지
흐려진다. 값이 대개 차 있는 업무 표에서는 우측 정렬이 그대로다.

**가로로 스크롤되는 표에서는 제목 칸을 접지 않는다.** 카테고리·과제명이 `…업무 자동 / 화`처럼
끝 글자만 넘어가면 같은 값이 행마다 다른 모양으로 읽힌다. `whitespace-nowrap`으로 두고 넘치는
폭은 표의 가로 스크롤이 감당한다.

### 배너 (상태 고지)
```
읽기 전용:  bg-warn-bg border-b border-warn-line text-warn   "읽기 전용 — 저장소 연결 실패"
데모 모드:  bg-raise border-b border-line text-ink-muted     "샘플 데이터 모드"
```
**둘의 문구와 색을 절대 섞지 않는다.** 하나는 사고고 하나는 의도다.

### "마지막 반영" 표시
모든 페이지 헤더 우측. `text-xs text-ink-muted`, **5일 초과 시 `text-warn` + 앰버 점.**

### 로그인 상태 표시 (T8)

상단 바 오른쪽 끝은 **세션이 있으면 계정, 없으면 역할 전환**이다. 둘은 같은 자리를 나눠 쓰고
**절대 함께 뜨지 않는다.**

| 상태 | 오른쪽 끝 |
|---|---|
| 로그인함 | `이메일` + 역할 배지(`대표·실장`/`팀장`/`부원`) + **[로그아웃]** |
| 프로필 없음 | `이메일` + `권한 미지정` + **[로그아웃]** — 세션은 있으니 나갈 길은 있어야 한다 |
| 데모·폴백 (세션 없음) | 지금까지와 같은 `?as=` 역할 전환. 「샘플 데이터 모드」 배너가 함께 뜬다 |

**로그인하면 역할 전환이 사라지는 이유는 그것이 거짓말이 되기 때문이다.** 세션이 있으면
`?as=`는 무시되므로(`ADR-026`) 버튼이 남아 있으면 눌러도 아무 일이 없고, 사용자에게 그것은
고장이다. 「당신은 부원입니다」와 「대표·실장으로 보기」를 한 화면에서 동시에 말하지 않는다.

- 로그아웃은 **링크가 아니라 폼**이다 (`<form method="post">`). `/api/auth/logout`이 `POST`만
  받는다 — 조회 메서드로 열어 두면 `<img>` 하나로, 혹은 프리페치 한 번으로 남을 로그아웃시킬
  수 있다.
- 이메일이 길면 **CSS로 자른다**(`truncate`). `title`·`data-*`에 전체 값을 심지 않는다 —
  툴팁도 화면 캡처에 남는다 (`S6`).
- 역할 라벨은 `src/lib/view/role-label.ts` 한 곳에서 온다. 역할 전환 버튼과 상단 바가 같은
  낱말을 써야 한다.

### 빈 화면은 다섯 갈래다

`X3`의 넷에 T8이 하나를 더했다. **늘어난 것이 아니라 「데이터 없음」이 갈린 것이다** —
로그인 뒤에는 「저장소가 비었다」와 「그 사람에게 보일 것이 없다」가 다른 사실이다.

```
데이터 없음         → "아직 데이터가 없습니다"           [샘플 불러오기] [시트 업로드]
담당자 미연결(member) → "담당자로 연결된 계정이 없어…"      (진입점 없음)
저장소 연결 실패     → "읽기 전용 — 저장소 연결 실패" 배너 + 편집 비활성
조회 실패           → error.tsx 바운더리                [다시 시도]
필터 결과 0건        → "조건에 맞는 업무가 없습니다"        [필터 초기화]
```

**두 번째 갈래에 진입점도 초기화 링크도 주지 않는다.** 그 사람이 시트를 올려도 자기 업무는
여전히 보이지 않고, 필터를 지워도 결과가 같다 — 필요한 것은 시트 담당자 이름과 계정의
연결이다 (`unknown_owner` · `PLAN.md` 결정 D). `admin`·`lead`에게는 이 문구를 보이지 않는다:
그들에게 빈 표는 다른 뜻이다.

어느 문구인지는 **화면이 정하지 않는다.** 페이지가 `lib/view/empty-reason.ts`로 고른 값을
`EmptyState`에 넘긴다. 컴포넌트가 역할을 다시 해석하면 「누가 무엇을 보는가」의 규칙이
셋째 자리에 생기고, 그 자리는 서버가 보지 않는다.

### 수정 폼 (`UC-16`)

사이드 패널의 「수정」 섹션. **상태 `select` + 진행률 `number` + [저장]** 이 전부다.

- **UI 숨김은 방어가 아니다.** 폼이 보이지 않는 것은 할 수 없는 조작을 눈앞에 두지 않는다는
  뜻일 뿐이고, 실제 거부는 `PATCH /api/tasks/[id]`가 한다(401·403). 보이는 조건(`canEdit`)은
  페이지가 `taskInScope`로 계산해 내려 준다 — 패널이 역할을 다시 읽지 않는다.
- 상태 목록은 `STATUS_SEMANTIC_MAP`의 키(`STATUS_OPTIONS`)다. 화면에 문자열을 다시 적지
  않는다 — 가운뎃점 하나만 달라도 사용자가 고른 값이 조용히 미매핑된다 (`ADR-009`).
- 빈 칸은 보내지 않는다. 「지운다」와 「안 바꾼다」를 버튼 하나로 뭉개지 않는다.
- **낙관적 업데이트를 하지 않는다.** 서버 응답을 받고 `router.refresh()`한다 — 먼저 그리면
  거부당한 수정이 잠깐 성공한 것처럼 보인다.
- 실패 문구는 **서버가 준 `message` 그대로**다. 화면이 「권한이 없습니다」를 지어내면 서버가
  코드를 바꿔도 화면은 옛 문장을 말한다.

## 레이아웃

### 앱 셸

```
┌────────────────────────────────────────────────────┐
│ 사이드바 │  상단 바  h-14   bg-panel border-b line  │
│ w-[220px]├────────────────────────────────────────┤
│ bg-panel │  본문  max-w-[1280px] mx-auto px-6      │
│ border-r │                                        │
└────────────────────────────────────────────────────┘
```

- 좌측 사이드바 고정 `w-[220px]`. **1024px 미만에서는 `w-14`로 줄여 아이콘만** 남긴다.
- 상단 바 `h-14`. 사이드바·상단 바 모두 `bg-panel` + `border-line`.
- 본문은 `max-w-[1280px] mx-auto px-6 pt-6 pb-16`. **아래 여백이 위보다 넓다** — 마지막 카드가 화면 바닥에 붙으면 스크롤이 끝난 것인지 잘린 것인지 알 수 없다.

### 폭

- 기준 폭 **1280px**, `max-w-[1280px] mx-auto px-6`. **1024px까지 레이아웃 유지** (`ADR-014`).
  그 아래는 깨지지 않고 읽히면 통과 — 별도 모바일 레이아웃은 만들지 않는다.
- **기준 높이 900px** (노트북 한 화면). 대시보드 요약이 여기 들어가야 한다 — 아래 참조.
- 대시보드 그리드: 섹션 전체가 하나의 `grid-cols-12`이고 섹션마다 `col-span-*`이 다르다.
- 정렬: **좌측 정렬 기본.** 수치만 우측 정렬. 중앙 정렬 금지(빈 상태 화면 제외).
- 간격: 카드 내부 `gap-3`, 그리드 `gap-4`. 본문 아래 여백 `pb-16`.
- 사이드 패널: 우측 고정 폭 `w-[640px]`(`max-w-[92vw]`), 페이지 위에 오버레이.
  480px에서 넓혔다 — 시트의 문서·캔바 URL이 두 줄로 접히고도 잘렸다. 이 패널은 70컬럼을
  다 보여 주는 자리라 값이 잘리면 존재 이유가 무너진다. 라벨-값 줄은
  `grid-cols-[120px_1fr]`이고 값 칸에 `min-w-0`과 `overflow-wrap: anywhere`를 준다
  (`min-w-0`이 없으면 띄어쓰기 없는 URL이 칸을 밀어내 패널 밖으로 넘친다).
  `http`·`https` 값 옆에는 [복사] 버튼을 둔다 — 링크는 열어 보는 것만큼 옮겨 붙는다.

### 대시보드는 한 화면이다 (`ADR-019`)

**스크롤해야 보이는 요약은 요약이 아니다.** 대시보드 섹션은 세로로 쌓지 않고 12열 그리드에
**흘려보낸다**(flow). 각 섹션이 폭(`SECTION_SPAN`)과 zone(`SECTION_ZONE`)을 갖는다 —
표는 `src/lib/view/role-layout.ts` 한 곳에 있다.

| zone | 섹션 (폭) | 규칙 |
|---|---|---|
| `summary` | KPI(12) · 팀별 현황(6) · 팀별 완료율(6) · 알림(6) · 상태 분포(6) | 펼친 채로 첫 화면에 전부 들어간다 |
| `detail` | 목표 대비 성과(4) · 주간 브리핑(4) · 승인 대기(4) | `<details>`로 **접어 둔다.** 제목 줄은 항상 보인다 |
| `table` | 업무 표(12) | 유일하게 스크롤 아래로 내려간다 |

`admin`으로 들어갔을 때의 결과다.

```
┌ KPI 10칸 (12) ─────────────────────────────────┐
├ 팀별 현황 (6) │ 팀별 완료율 (6) ────────────────┤
├ 알림 (6) ─────│ 상태 분포 (6) ──────────────────┤
├ ▸목표(4) ▸브리핑(4) ▸승인 대기(4) ─────────────┤  ← 여기까지 1280×900 안
└ 업무 표 (12) ──────────────────────────────────┘  ← 아래로
```

`member`는 KPI가 **축약 3칸**이라 12칸을 혼자 쓰면 타일 사이가 화면 폭만큼 벌어진다.
그래서 상태 분포 칸에 **그 위로 쌓아** 알림 오른쪽에 함께 둔다. 10칸짜리 전체 KPI는
그대로 한 행을 다 쓴다 — 5열 그리드를 6칸에 밀어 넣으면 라벨이 두 줄로 접힌다.

```
┌ 업무 표 (12) ──────────────────────────────────┐  ← `member`는 자기 업무가 맨 위
│              │ KPI 축약 3칸 (6) ───────────────┤
├ 알림 (6) ─────│ 상태 분포 (6) ──────────────────┤
```

**짝은 화면이 정한다** (`DASHBOARD_LAYOUT`·`TEAM_PAGE_LAYOUT`의 `groups`). 자동 배치는
빈칸을 줄일 뿐 **무엇과 무엇이 나란히 서야 하는지**는 모른다. 두 짝의 근거는 이렇다.

- **팀별 현황 + 팀별 완료율** — 같은 팀 축을 표와 그림으로 보는 둘이다. 세로로 쌓으면
  같은 팀을 확인하는 데 눈이 두 번 왕복한다.
- **알림 + 상태 분포** — 「지금 손댈 것」과 「전체 그림」. 알림은 데이터에 따라 길어지고
  막대 차트는 그만큼 늘어나므로 **높이가 서로 맞는다.** 폭은 **6 + 6으로 같다** — 어느 쪽도
  곁다리가 아니라서 한쪽이 좁으면 그쪽이 부속처럼 읽힌다.
- **펼친 내용은 요약 줄에 붙는다.** 둘 사이에 여백과 테두리가 두 겹 들어가면 펼친 카드가
  요약 줄에 딸린 것이 아니라 그 아래 놓인 **별개 카드**로 읽힌다. 카드의 위쪽 모서리와
  테두리를 지워 이어 붙인다.
- **접힌 카드는 펼쳐도 폭이 그대로다.** 자기 4칸 안에서 아래로 자란다. 예전에는 펼치면
  12칸으로 넓혔는데, 셋이 나란히 접혀 있다가 하나만 폭 전체를 차지하면 다른 둘이 아래로
  밀려나 **화면이 통째로 재배치된 것처럼** 보였다. 좁은 칸에서 넘치는 표·마크다운은 각자
  가로 스크롤을 들고, 브리핑 원문은 줄을 접지 않는다(접으면 마크다운 표의 칸이 어긋난다).
- 행 배치는 **first-fit**이다 — 앞 행에 자리가 남으면 거기 채운다. 세 역할 모두 빈 칸이
  거의 남지 않는 폭 조합(12 / 6+6 / 12)이라 요약이 필요 이상으로 길어지지 않는다.
- **알림은 12칸을 혼자 쓰지 않는다.** 폭을 다 먹으면 항목 이름과 건수 사이가 화면 폭만큼
  벌어진다 — 이 패널을 좁힌 것이 재배치의 출발점이었다. 패널은 **제 칸 폭을 보고** 단 수를
  정하므로(`@container`) 7칸 이상이면 두 단이 되고, 뷰포트가 아니라 칸을 보기 때문에 어느
  화면에 두든 규칙이 같다.

### 같은 행의 카드는 높이를 맞춘다

테두리가 어긋나면 두 카드가 다른 층에 있는 것처럼 읽힌다. 그래서 행은 `items-stretch`이고
칸 안의 카드는 `h-full`이다. **늘어난 높이를 빈칸으로 두지 않는 것이 이 규칙의 절반이다** —
늘어나는 카드는 *콘텐츠로* 채운다.

| 카드 | 늘어난 높이를 무엇이 먹나 |
|---|---|
| 팀별 완료율 | 막대 차트 (`flex-1` · `maintainAspectRatio: false`라 컨테이너를 따른다) |
| 알림 | 묶음 목록 (`flex-1`), 넘치면 **목록만** 스크롤 — 제목은 늘 보인다 |
| 상태 분포 | 아무것도 먹지 않는다 — **높이가 확정 값**이다 (아래) |

**늘어나는 차트는 부모 높이가 확정일 때만 늘어난다.** 부모 높이가 내용으로 정해지는 flex 칸
안에서 `responsive` 캔버스는 제 크기를 다시 부모에 되먹여 **끝없이 자란다** — 막대 여섯 개짜리
상태 분포가 500px을 넘겨 옆의 알림 카드를 통째로 빈 채 끌고 나온 것이 그 경우다. 알림 묶음을
접으면서 「알림이 길어지는 카드」라는 전제가 뒤집혔고, 그래서 상태 분포는 `min-h` + `flex-1`이
아니라 **확정 높이**(`h-[152px]`)를 쓴다. 막대 여섯 줄과 x축이 들어갈 만큼이고 그 이상은
데이터가 아니라 여백이다.

**단, 접히는 카드가 있는 행은 높이를 맞추지 않는다**(`items-start`). 사용자가 펼치는
순간 그 칸이 길어지면서 **옆 칸까지 끌고 가기** 때문이다 — 목표 대비 성과를 펼쳤더니
알림 아래가 통째로 비는 일이 그것이다. 높이 정렬은 카드가 스스로 늘어날 때만 값을 한다.

**높이가 변하는 카드 옆에는 함께 늘어날 수 있는 카드만 세운다.** 알림은 데이터에 따라
길어지므로, 짧고 고정된 카드(상태 분포 스택 바)를 옆에 두면 그쪽이 통째로 빈다. 팀 화면이
정확히 그 경우라 거기서는 알림을 **혼자** 세웠다 — 옆에 카드가 없으면 어긋날 높이도 없다.
알림 자체에도 상한(`max-h`)이 있어서, 옆 카드가 없을 때 목록이 화면을 밀어내지 않는다.

### 팀 화면은 같은 규칙에 **폭만 다르다**

`layoutFor(role, TEAM_PAGE_LAYOUT)` — 상수는 `role-layout.ts`에 있고 화면과 테스트가 같은
값을 본다. 이 화면에는 전사 요약표·완료율 차트·승인 대기함·브리핑이 없어서 **알림 옆에
세워 둘 만큼 긴 카드가 하나도 없다.** 그래서 짧은 둘(상태 분포·목표 대비 성과)을 **세로로
쌓아** 그 자리를 채운다. 알림이 12칸을 다 먹지 않아 이름과 건수도 붙어 있고, 7칸이면
패널이 두 단으로 갈라진다.

```
┌ KPI 10칸 (12) ─────────────────────────────────┐
│                      │ 상태 분포 (5) ──────────┤
├ 알림 (7) ────────────┤ ▸목표 대비 성과 (5) ────┤
└ 업무 표 (12) ──────────────────────────────────┘
```

**한 칸에 섹션을 세로로 쌓을 수 있다** (`['charts', 'goals']`). 짧은 카드 둘을 포개어
긴 카드 옆을 채우는 자리이며, 그 칸 안에서는 접힌 카드가 펼쳐져도 폭이 넓어지지 않는다.

배치를 그리는 것은 두 화면 다 `components/shell/section-grid.tsx` **하나**다. 화면마다
복사하면 한쪽만 고쳐지는 날이 오고, 그날부터 두 화면의 카드 폭이 다른 이유를 아무도
설명하지 못한다.

**zone 순서는 역할이 정한다.** `SECTION_ORDER`(역할별 배열)에서 각 zone이 **처음 등장하는
순서**가 곧 zone 순서다. 그래서 `admin`·`lead`는 `summary`부터, `member`는 `table`(자기 업무)
부터 시작한다 — 완료 기준 7의 「무엇이 맨 위냐」가 그대로 보존되고, **어느 역할도 섹션을
잃지 않는다.** 접는 것은 레이아웃이고 삭제는 권한이다. 권한은 T8이다.

## 타이포그래피

| 용도 | 스타일 |
|------|--------|
| 페이지 제목 | `text-xl font-semibold text-brand` |
| 섹션 제목 | `text-sm font-semibold text-brand` |
| KPI 수치 | `text-xl font-semibold tabular-nums text-ink` |
| KPI 라벨 | `text-xs text-ink-muted` |
| 표·본문 | `text-sm text-ink-body` |
| 보조 설명 | `text-xs text-ink-muted` |

숫자는 **전부 `tabular-nums`**. 자릿수가 흔들리면 표가 읽히지 않는다.

## 차트

- **가로 막대 둘뿐이다** — 상태 분포(상태별 건수)와 팀별 완료율(팀별 %). 그 외 차트 타입을
  추가하지 않는다. **도넛도 스택 바도 쓰지 않는다** (`ADR-019`): 도넛은 세로 300px를 쓰면서
  KPI와 같은 사실을 두 번 말했고, 스택 바는 세로를 안 먹어서 **옆에 세울 카드가 없었다.**
- 막대 두께에 상한을 둔다(`maxBarThickness: 22`). 카드가 옆 카드를 따라 길어질 때 막대가
  두꺼워지는 게 아니라 **사이가 벌어져야** 한다 — 굵어지면 그림이 아니라 벽지가 된다.
- 축 눈금은 정수다(`precision: 0`). 건수 축에 `0.5`가 찍히면 「반 건」이 있는 것처럼 보인다.
- 계열이 하나뿐인 차트는 범례를 끈다 — y축 라벨이 이미 같은 말을 한다.
- 계열 색은 상태 배지의 명도 스케일을 그대로 쓴다. 흰 패널(`#ffffff`) 위에서 서로 구분돼야
  한다: `#aab2be`(예정) · `#3c434d`(진행) · `#7d8694`(검토) · `#c9d0d8`(완료) ·
  `#dbe0e6`(기타) · `#dc2626`(지연). **가장 옅은 「기타」도 빈 트랙(`#f0f2f5`)보다 진하다** —
  같으면 조각이 있는데 없는 것처럼 보인다.
- 그라데이션 채움·그림자·3D 금지. 격자선은 `#e2e5ea` 한 겹, 축 라벨은 `#697280`.
- 범례는 차트 하단 좌측 정렬. 애니메이션은 끈다(`animation: false`) — 매번 튀면 도구가 아니다.

## 애니메이션

- 사이드 패널 슬라이딩: `translate-x` **200ms** ease-out. Esc·오버레이 클릭으로 닫힌다.
- 리프레시 중 스켈레톤: 불투명도 페이드 **150ms**.
- **그 외 모든 애니메이션 금지.** 특히 hover 시 확대(scale), 그림자 증폭, 글로우.

## 아이콘

- SVG 인라인, `strokeWidth 1.5`, 크기 16px 기본.
- **아이콘 컨테이너(둥근 배경 박스)로 감싸지 않는다.**
- 알림 종류는 아이콘이 아니라 **한글 라벨**로 구분한다(마감 임박 / 장기 미갱신 / 담당자 미지정 / 기한 미설정).
- 목록 줄 끝의 `›` 화살표는 **종류를 말하는 아이콘이 아니라 「눌린다」를 말하는 표시**다.
  위 규칙과 충돌하지 않는다 — 모든 줄에 같은 모양으로 붙어서 아무것도 구분하지 않는다.

## 목표 대비 성과의 톤

목표 대비 성과 섹션에서 **달성률 미달을 빨강으로 칠하지 않는다.**

- **빨강은 업무 지연 전용이다.** 목표 미달까지 빨강이면 화면에 빨강이 두 뜻으로 존재하고,
  둘을 구분하려면 사람이 매번 어느 섹션인지 확인해야 한다. 지연이 묻힌다.
- 달성률 **100 미만은 주의(`text-warn`)**, 그 외(100 이상·미측정)는 **무채색**이다.
- 달성률 막대·수치도 같은 규칙을 따른다. 초과 달성을 초록으로 칠하지 않는다.

## 링크 렌더링 (보안)

시트의 하이퍼링크 셀을 사이드 패널에 렌더할 때 **`http`·`https` 스킴만 앵커로** 만든다.
나머지(`javascript:` 등)는 텍스트로만 표시. 외부 링크에는 `rel="noopener noreferrer"`.
