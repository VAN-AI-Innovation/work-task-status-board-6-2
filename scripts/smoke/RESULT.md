`## N. 대분류` → `h2` (9건), `### N-M. 과제명` → `h3` (20건)이 그대로 성립한다.
`PLAN.md`「5. 독스 → 배정표」가 전제한 매핑이 실측으로 확인됐다.

### `p`로 강등된 번호 문단

**6건.** `h2`·`h3`이 각각 12·50건 잡힌 상태이므로 heading 강등 신호가 아니다.
본문 안의 번호 목록(「워크로드 공유」 절의 P0/P1 블록 등)으로 보이며, `PLAN.md`가
이미 `workload-parser.ts`로 분리 파싱하기로 한 영역과 겹친다.

### mammoth `messages` — 스타일 경고

```
[warning] Unrecognised paragraph style: 'Title' (Style ID: Title)
```

**경고는 이 1건뿐이다.** 문서 제목 스타일이며 `h1~h3` 아웃라인과 무관하다.
`Heading 1~3`·`제목 1~3` 계열은 경고가 없다 — mammoth 기본 styleMap이 전부 인식했다.

### 필요한 styleMap

**없다.** 기본 옵션으로 PASS했으므로 `docx-reader.ts`는 `mammoth.convertToHtml({ path })`를
옵션 없이 호출하면 된다. (`Title`을 아웃라인에 넣고 싶다면 선택적으로
`"p[style-name='Title'] => h1:fresh"` 한 줄을 붙일 수 있으나, 문서 제목은 과제 아웃라인이
아니므로 T7에서 필요해질 때 판단한다.)

### T7에 주는 결론

- **T7 예상시간 `L`을 유지한다.** `ADR-010`·`TICKETS.md` T7의 최대 변수(mammoth 인식)가
  해소됐고, styleMap 커스터마이즈 작업이 불필요하다.
- 3차 대안(문단 텍스트 패턴 매칭)은 **쓰지 않는다.** `PLAN.md` `H8`의 탈출구로만 남긴다.
- `h3` 50건 중 아웃라인 과제는 `N-M.` 접두사를 가진 20건이다. 나머지 30건은 과제가 아닌
  절 제목이므로, `outline-builder`는 **태그 깊이만이 아니라 번호 접두사도 함께** 봐야 한다.
  이 판별은 T7 범위다.

## A7 — 시트 크기·규모 실측 (`.xlsx`)

- 측정 스크립트: `node scripts/smoke/sheet-metrics.mjs`
- 대상: `smoke-input/`의 업무 시트 `.xlsx` 1개 (실업무 원본 — 커밋 대상 아님)
- 라이브러리: `exceljs@4.4.0`

### 파일 크기

- **100,618 bytes (0.10 MB)**
- 4MB 한도의 **2.4%**만 쓴다. 여유 3.90 MB
- **4MB 한도 판정: PASS (단일 업로드 가능)** — 탭별 분할 업로드(`UC-04`)는 예외 경로로 남는다

### exceljs 열기

**성공.** `new ExcelJS.Workbook()` → `workbook.xlsx.readFile(path)`가 Google Sheets
내보내기 파일을 그대로 읽는다. **T2 착수를 막는 요인은 없다.**

### 워크시트

**5개** — `00_통합 대시보드` · `01_편집팀` · `02_촬영·기획팀` · `03_마케팅·관리팀` · `99_설정`

`PLAN.md`「A. 엑셀」이 적은 탭 5개와 일치한다. 다만 설정 탭의 실제 이름은 `설정`이 아니라
**`99_설정`**이다 — `tab-detector`(T2)의 이름 정규식이 접두사를 감안해야 한다.

| 시트 | rowCount | columnCount | dimensions | 값 있는 셀 | dimensions 셀 | row×col |
|---|---|---|---|---|---|---|
| `00_통합 대시보드` | 1001 | 26 | A1:J60 | 144 | 600 | **26,026** |
| `01_편집팀` | 60 | 16 | A1:P60 | 352 | 960 | 960 |
| `02_촬영·기획팀` | 60 | 72 | A1:BS60 | 1,565 | 4,260 | 4,320 |
| `03_마케팅·관리팀` | 70 | 30 | A1:AD70 | 406 | 2,100 | 2,100 |
| `99_설정` | 101 | 30 | A1:AB29 | 263 | 812 | 3,030 |

- **전체 셀**: 값 있는 셀 **2,730개** / `rowCount × columnCount` 기준 **36,436개**
- 시트 하나 최대: 값 있는 셀 1,565 / dimensions 4,260 / `row×col` **26,026**

### S2 한도 판정

**시트 수 5개 ≤ 20개 — PASS.**

**셀 수: `row×col` 기준으로 재면 FAIL이다.** `00_통합 대시보드`의 `rowCount × columnCount`가
**26,026**으로 시트당 20,000 한도를 넘는다. 즉 **정상 업무 파일이 압축 폭탄으로 오탐된다.**

원인은 데이터가 아니라 내보내기 형식이다. 이 시트의 `dimensions`는 `A1:J60`(600셀)인데
`rowCount`가 **1001**이다 — Google Sheets가 기본 1000행 그리드를 통째로 내보내고,
ExcelJS의 `rowCount`는 값 없이 서식만 있는 행까지 센다. 값이 있는 셀은 **144개뿐**이다.

세 기준의 최대 시트 값이 갈린다:

| 세는 기준 | 최대 시트 값 | 20,000 한도 |
|---|---|---|
| 값 있는 셀 | 1,565 | PASS (7.8%) |
| `dimensions` 사각형 | 4,260 | PASS (21.3%) |
| `rowCount × columnCount` | **26,026** | **FAIL (130%)** |

`02_촬영·기획팀`의 72컬럼은 세 기준 어디서도 문제가 아니다. 걸리는 건 대시보드 탭의
빈 행 패딩 하나뿐이다.

### T5에 주는 결론

1. **4MB 한도(`A7`)는 그대로 쓴다.** 실측이 한도의 2.4%다. `/upload` 화면의 기본 안내는
   단일 파일 업로드이고, 탭별 분할은 부분 업로드(`UC-04`) 용도로만 남는다.
2. **`S2`의 "시트 20개"는 그대로 쓴다.** 실측 5개다.
3. **`S2`의 "행 × 열 ≤ 20,000 셀/시트"는 그대로 쓸 수 없다.** 지금 문구대로
   `rowCount × columnCount`로 세면 이 파일이 `ARCHIVE_LIMIT_EXCEEDED`로 거부된다.
   T5 착수 전에 둘 중 하나로 확정해야 한다:
   - (a) **세는 기준을 바꾼다** — `dimensions` 사각형 또는 값 있는 셀 기준. 실측 여유가
     각각 4.7배·12.8배로 넉넉하다. 다만 압축 폭탄이 `dimensions`를 위조할 수 있으므로
     방어 강도가 `row×col`보다 약하다.
   - (b) **한도 숫자를 올린다** — `row×col` 기준을 유지하고 시트당 상한을 상향.
     Google Sheets 기본 그리드(1000행 × 26열 = 26,000)를 감안하면 최소 5만 이상이어야
     한 탭짜리 내보내기가 통과한다.
   - 실측이 뒷받침하는 조합은 **(a)+(b)** 다 — `dimensions` 기준으로 세되 한도를
     여유 있게 잡는 쪽. 최종 결정은 T5 티켓에서 방어 로직과 함께 확정한다.
4. `99_설정` 탭 이름에 숫자 접두사가 붙어 있다. `tab-detector`(T2)와 `SETTINGS_TAB_MISSING`
   판정이 `설정` 정확 일치가 아니라 부분 일치를 써야 한다.

### 이 표가 무엇을 증명하고 무엇을 증명하지 않는가

**증명한다**: T8 완료 기준 **5**(조회가 사용자 JWT로 나가 RLS가 실제로 걸린다)와 완료 기준
**1**의 DB 층. 세 건수 `10 / 6 / 2`는 `service_role`로 그때그때 센 기대값(전체 / lead 팀 /
member 담당)과 각각 일치했고 셋이 서로 다르다. 6·8은 **다른 자물쇠 둘**이다 — 6은 정책이
어느 **행**을, 8은 `grant update (status, progress, updated_at)`이 어느 **컬럼**을 막는지 잰다.

**증명하지 않는다**: 완료 기준 **2**의 API 층. 여기서 재는 것은 PostgREST 직결이고,
`PATCH /api/tasks/[id]`가 `FORBIDDEN`을 돌려주는지는 그 라우트가 생긴 뒤(step 9)에 잰다.
완료 기준 **6**(`?as=`의 프로덕션 차단)도 여기 없다 — 그것은 세션 계층의 일이다.
